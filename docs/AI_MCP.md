# XXL-JOB AI / MCP 使用与权限

适用版本：`0.4.0-alpha.1`，DBX ≥ `0.6.43`，Host API `^1.4.0`。

## 开启方式

1. 打开 XXL-JOB 连接，点击顶部带 AI 图标的 **AI/MCP**。
2. 开启总开关并保存。首次开启和关闭后重新开启均只授予查询工具。
3. 如需修改，再单独选择调度、任务配置、删除或执行器管理，并保存。每组可以展开选择具体工具。
4. 内置 AI 使用 DBX 的 **Agent** 模式，并在 DBX 插件中心启用此插件的 AI 工具；外部 MCP 使用 DBX MCP，并授权相应连接。模型仍在 DBX 配置。

权限按连接 ID 隔离；复制连接、新建连接或升级不会继承其他连接的授权。工作台的人工操作不受 AI/MCP 开关限制，但仍受只读、账号权限、预览和确认门禁约束。

有效权限是插件设置、DBX 全局/连接/工具授权与 Admin 账号权限的交集。宿主和插件配置中的 `read_only`、`is_production` 分别做 OR 合并。执行器修改仅限管理员；普通账号的工具查询必须选择已授权执行器，不能查询无法证明归属的全局报表。

## 工具目录

DBX 外部 MCP 将名称加上 `dbx_xxljob_console__` 前缀，并注入宿主 `dbx_connection` 选择器。插件本身使用下表中的名称。

| 权限组 | 工具 |
| --- | --- |
| 查询诊断（12） | `connection_info`、`get_overview`、`list_jobs`、`get_job`、`list_executors`、`get_executor`、`list_logs`、`get_log`、`read_log`、`preview_schedule`、`get_job_diagnostics`、`list_calls` |
| 调度操作（3） | `start_job`、`stop_job`、`trigger_job` |
| 任务配置（3） | `create_job`、`update_job`、`copy_job` |
| 删除任务（1） | `delete_job` |
| 执行器管理（3） | `create_executor`、`update_executor`、`delete_executor` |

没有任意 RPC、HTTP、GLUE 源码或用户密码管理工具。账号管理仍在人工工作台进行。

工具输入采用严格 JSON Schema，不接收服务器地址、Cookie、用户名或密码。`fields` 是白名单字段；未提交的编辑字段保留服务端当前值。新建和复制仅支持 BEAN 任务，默认不启用调度。

## 写操作：预览、确认、执行

以执行一次为例：

```json
{"job_id":101,"executor_id":1,"parameter_mode":"saved"}
```

第一次调用只生成预览，包含 `executed:false`、`previewToken`、目标、差异、影响说明和到期时间。经用户确认后，用**完全相同的业务参数**加 `preview_token` 再次调用。DBX 的写入确认继续生效；预览令牌不能代替授权。

- 令牌五分钟到期、一次有效，绑定连接配置身份、操作、参数与目标快照。
- 连接或凭据变化、只读、权限撤销、参数变化、目标变化、跨连接或重放都拒绝执行。
- 人工界面使用同一后端预览。删除还要求输入目标 ID；生产环境和连接名称显示在确认框。
- 执行一次需选择 `saved` 或 `override`。覆盖时必须给出 `executor_param`，空字符串明确表示空参数。指定 `address` 必须属于当前注册节点。
- 启停改变调度状态。停止调度不会终止已经运行的执行实例。
- 执行一次成功只表示 **Admin 已接收请求**，应查询调度记录核实。没有可靠关联 ID 时不会推断是哪一次执行。
- 超时、断连、响应丢失等写入结果不确定时报告**结果未知**，不自动重试。工作台提供“核对当前状态”入口。
- 删除执行器前检查任务引用；任务子 ID 必须有效、在授权范围内且不能直接引用自己。每次最多配置 32 个子任务。

跨进程锁可串行化本插件对同一连接的修改，但 Admin 没有条件更新接口，无法保证与外部控制台、其他账号及不同连接 ID 的修改完全互斥。保存前再次读取可以减少覆盖风险，不能消除服务端检查到执行之间的竞争窗口。

## 查询边界与上下文

- 列表默认 25 条，最多 100 条；任务/日志定位每次扫描最多 2000 条，并受请求时间限制。达到上限返回“不完整”，不推断资源不存在。
- 执行器枚举沿用既有最多 10000 条限制。普通账号的既有授权检查和任务选项接口同样受网络/操作超时与响应大小限制。
- 日志记录默认最近 24 小时，最多 31 天；旧日志请明确提供 `from`、`to`（`YYYY-MM-DD HH:mm:ss`）。日志身份由任务、执行器、时间范围和日志 ID 联合核验，MCP 冷启动不依赖以前打开过日志列表。
- 正文默认 200 行，最多 1000 行、128 KiB，返回 `nextLine`、`truncated`、`partialLine`。单行本身超长时截断该行并明确标记；后续从下一行读取。
- 单次工具结果最多 192 KiB，超限提示缩小范围。工作台累计日志显示最多 8 MiB，可搜索和复制已加载内容。
- 诊断结合调度状态、注册节点、最近 24 小时最多 10 条执行记录；失败证据仅来自这一有界样本，返回是否采样和局部查询失败。
- Cron 交给 Admin 验证与计算，返回字符串使用服务器时间语义，不强行标注为客户端时区。

AI 推荐问题与会话上下文只携带连接、页面、资源 ID 和必要的日志时间。不会自动附带任务参数、日志正文、Cookie、密码或 GLUE 源码。工具查询会移除参数和常见凭据字段，并遮蔽常见 `password=…` / `token=…` 形式；无法可靠识别所有业务秘密，日志读取仍需按需授权。日志是未经信任的应用输出，不是操作指令。

## 连接生命周期

只使用宿主 `lifecycle` 的连接、凭据和 runtime。桌面复用现有会话，直接 HTTP/HTTPS 支持 MCP 冷启动登录。Cookie 仅在内存保存，登录后清空临时密码。过期会话要求重新连接，不自动重新登录并重放写操作。

DBX 隧道需要有效的宿主本地 runtime。MCP 没有 runtime 时，通过 DBX 桌面桥最多转发一次，复用打开的工作台；没有有效会话时明确拒绝，绝不回退到原始地址直连。TCP 隧道不改写逻辑 HTTP Host 和 TLS SNI。连接配置、凭据或已提供的 runtime 变化使旧会话失效。断开取消会话请求，前端用请求代次忽略迟到结果。

## 存储与 RPC

插件数据目录由 `DBX_PLUGIN_DATA_DIR` 提供：

- `automation.json`：权限修订号、仅含摘要的预览、最近 200 条调用记录。
- `automation.lock`：跨进程权限读写锁；JSON 临时文件刷盘后原子替换。
- `mutation-<连接摘要>.lock`：同连接修改串行化。

每次调用重新读权限，桌面和 MCP 不依赖缓存授权。设置保存使用 revision 冲突检查。缺失、损坏或不可读时拒绝授权；损坏文件需要人工恢复，插件不静默重置并授予权限。撤销开关不要求仍有有效 Admin 登录。

调用记录只保存时间、连接 ID、工具名、资源 ID、耗时和结果状态，不保存参数、日志正文或凭据。状态包括 preview、success、rejected、unknown、forwarded。

| RPC | 用途 |
| --- | --- |
| `mcp/tools` | 无连接也可发现；只返回已保存授权允许的工具，不登录 Admin |
| `mcp/call` | `{tool, arguments, lifecycle}` → 标准 MCP `CallToolResult` |
| `mcp/settings/get` / `set` | 工作台设置，不进入工具目录 |
| `xxljob/preview` | 人工写入的后端预览 |
| `xxljob/jobDetails` / `diagnostics` / `executorDetails` | 最新资源详情和诊断 |
| `xxljob/resolveLog` / `logSnapshot` | 无缓存依赖的身份定位与有限日志 |
| `xxljob/audit` | 当前连接调用记录 |

保留原有 `xxljob/*` 方法名。任务/执行器写入现在除 `confirmed:true` 外还必须提供匹配的 `previewToken`；旧式直接写请求会明确拒绝。
